## A matrix is a function

A matrix $A$ with $m$ rows and $n$ columns is a function that takes a vector $x \in \mathbb{R}^n$ and returns $y = Ax \in \mathbb{R}^m$. It's **linear**: $A(\alpha x + \beta z) = \alpha Ax + \beta Az$. Conversely, every linear function between such spaces is a matrix, so "linear map" and "matrix" are the same idea.

There are two ways to read $Ax$, and you'll want both:

- **The column picture.** $Ax = x_1 a_1 + x_2 a_2 + \dots + x_n a_n$, a linear combination of the columns $a_j$. Column $j$ is exactly where the basis vector $e_j$ lands.
- **The row picture.** Entry $i$ of $Ax$ is the dot product of row $i$ with $x$. A linear model's predictions $Xw$ are one dot product per sample.

<Viz name="MatrixMap" />

Doing one map after another is a matrix product: first $A$, then $B$, is $B(Ax) = (BA)x$. The first map sits next to $x$. Shapes have to chain, $(m \times n)(n \times p)$, and order matters: rotating and then shearing isn't the same as shearing and then rotating.

For a square matrix, the **determinant** is the factor by which it scales areas (volumes in higher dimensions), with a negative sign if it flips orientation. A determinant of zero means the map squashes the plane onto a line or a point. Try the "rank 1" preset.

## Rank, column space and null space

Three linked ideas tell you what a matrix can and can't do.

- The **column space** is every output $Ax$ can produce: all combinations of the columns.
- The **rank** is the dimension of the column space: the number of independent columns (always equal to the number of independent rows).
- The **null space** is every input that maps to zero: $Ax = 0$.

They're tied together by **rank–nullity**: rank + dim(null space) = $n$, the number of columns. Every column that fails to add a new direction adds a dimension to the null space instead.

For a design matrix $X$ (one row per sample, one column per feature), a nonzero null-space vector $v$ means $Xv = 0$: some combination of features is identically zero. Then $w$ and $w + c\,v$ give exactly the same predictions for every $c$, so the coefficients aren't unique. Two classic ways to get there:

- **The dummy-variable trap.** An intercept plus an indicator for every season: the indicators always add up to the intercept column, so (1, −1, −1, −1, …) is in the null space. That's the warning Dev saw.
- **One sensor logged twice.** A temperature in °F is $32 + 1.8\,T_{°C}$: a combination of the intercept and the °C column.

In floating point, "exactly dependent" almost never happens: rounding turns zeros into 10⁻¹⁶. So numerical rank counts directions above a tolerance, as `np.linalg.matrix_rank` does (Lesson 5 shows what it measures). Scale matters too: a column 10¹⁰ times smaller than its neighbours looks like rounding noise unless you scale the columns first.

## Solving Ax = b

When $A$ is square with full rank, $Ax = b$ has exactly one solution. Compute it with `np.linalg.solve(A, b)`, which factors $A = LU$ (with row pivoting) and then solves two triangular systems. Don't compute `np.linalg.inv(A) @ b`:

- **It's slower.** Forming the inverse takes about three times the arithmetic of one factorization.
- **It's less accurate.** On the 8 × 8 Hilbert matrix (a famously ill-conditioned test case), the relative residual $\|Ax - b\|/\|b\|$ is about 10⁻¹⁶ through `solve` and about 10⁻⁸ through `inv`.

If you need to solve with the same matrix many times, factor once and reuse the factors (`scipy.linalg.lu_factor` and `lu_solve`, or `cho_factor` and `cho_solve` for symmetric positive definite matrices, which you'll meet in Lesson 4).

## Condition numbers: how much can errors grow?

Even a perfect algorithm can't beat the problem it's given. The **condition number** $\kappa(A)$ is the ratio of the most a matrix stretches any direction to the least (Lesson 5 makes that precise with singular values). It bounds how much relative errors in the data can grow in the answer:

$$
\frac{\|\Delta x\|}{\|x\|} \lesssim \kappa(A)\,\frac{\|\Delta b\|}{\|b\|}
$$

Since float64 stores about 16 significant digits, the rule of thumb is that **you lose about log₁₀ κ of them**. Some numbers from this course's experiments:

| Matrix | κ | What it means |
|---|---|---|
| Identity, rotations | 1 | No amplification at all |
| Dev's two inlet sensors plus an intercept | about 600 | Coefficients wobble; their sum doesn't |
| Powers of temperature up to $T^5$, $T$ from 15 to 35 °C | 4 × 10¹⁰ | Only 5 or 6 digits survive |
| Same features after standardizing $T$ | 37 | Essentially no loss |
| 12 × 12 Hilbert matrix | 2 × 10¹⁶ | `solve` returns an answer 10–20% wrong, with a residual of 10⁻¹⁶ |

The last row is worth pausing on. `solve` is **backward stable**: it returns the exact solution of a problem within rounding error of yours, which is why its residual is tiny. When κ is around 10¹⁶, the exact solution of a nearby problem can be far from the exact solution of yours. That's the problem's fault, not the algorithm's, and no algorithm can fix it. You fix it by reformulating: scale and center the features, remove redundant ones, or regularize (Module 6).

A small determinant doesn't mean ill-conditioned. In 20 dimensions, $0.1\,I$ has determinant 10⁻²⁰, yet κ = 1: it shrinks every direction equally, and solving with it loses nothing. The determinant multiplies the stretches; conditioning compares them.

<Craft title="Matrix habits worth keeping">
- `np.linalg.solve` for square systems, `np.linalg.lstsq` for rectangular ones (Lesson 3), a Cholesky factorization for symmetric positive definite ones. Never `inv` followed by a product.
- Check `np.linalg.cond(X)` before interpreting coefficients. With κ in the hundreds, compare combinations that the data pin down (Dev's sum), not individual coefficients.
- Standardize a feature *before* building powers or interactions from it.
- Read library warnings about singular or ill-conditioned matrices as information about your features, not noise to suppress.
- Stable predictions with unstable coefficients is a classic sign of near-collinearity: the model is fine for prediction and useless for explanation.
</Craft>
