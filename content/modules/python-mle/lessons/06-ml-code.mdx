## Functions first, classes for learned state

Most ML code should be plain functions: data in, data out, no hidden state. That makes it easy to test and to reuse. Reach for a class when something is *learned* from data and used later. A scaler learns statistics during training and applies them to new data; a model learns weights. Two Python features keep classes honest:

- **Type hints** (`def fit(self, X: NDArray[np.float64]) -> "MedianScaler":`) document intent, and checkers such as mypy or pyright catch mismatches before runtime. A shape or type annotation is unit-checking for code.
- **Dataclasses** turn a configuration into a small, readable record. With `frozen=True`, a config can't be modified halfway through a run, so the settings you logged are the settings you used.

**Protocols** describe what an object can do rather than what it inherits from. `class Forecaster(Protocol): def fit(self, X, y) -> Self: ...` accepts any object with a matching `fit` method, which is how Python's typing expresses duck typing.

## The estimator contract

scikit-learn's tools (pipelines, `clone`, cross-validation, grid search) work with any class that follows a short contract. Most of the ML ecosystem copies it.

1. `__init__` **only stores its arguments, unchanged.** No validation, no computation, no data.
2. `fit(X, y=None)` learns from data, stores the results in attributes **ending in an underscore** (`mean_`, `coef_`), and **returns `self`**.
3. `transform` and `predict` use only what `fit` learned, and raise `NotFittedError` if `fit` hasn't run.

Rule 1 looks fussy until you see why. To try a new setting, grid search calls `clone`, which rebuilds your estimator from `get_params()`. If `__init__` converted or validated an argument, the rebuilt object wouldn't match the original, so `clone` refuses. Rule 2's underscore lets tools tell settings (chosen by you) from learned state (chosen by the data).

## Reproducible randomness

Random numbers drive train/test splits, initialization, bootstrap estimates and data augmentation. To get the same results tomorrow:

- Create a generator, `rng = np.random.default_rng(seed)`, and **pass it** to whatever needs randomness. Don't call `np.random.seed`: it resets one global generator shared by your whole program and every library in it.
- For parallel workers, don't reuse one seed or count up by hand. `np.random.SeedSequence(seed).spawn(n)` gives n independent, reproducible child streams.
- Log the seed with the results, like any other setting.

<Craft title="Code review checklist for ML code">
- Settings are explicit and logged, ideally in a frozen config, with no magic numbers buried in functions.
- Nothing learned leaks across a train/test boundary: every statistic is computed in `fit` on training data only.
- Randomness comes from a seeded generator that's passed in; no global seeding.
- No mutable default arguments, and no class-level lists or dicts shared by every instance.
- Type hints on public functions, checked in CI.
</Craft>
