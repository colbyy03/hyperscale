## Why Python loops are slow

A Python `for` loop over a NumPy array does real work on every element: it creates a Python float object, looks up the `+` operator, checks types, and stores the result. That overhead is around tens of nanoseconds per element, and it dwarfs the actual arithmetic.

A **vectorized** expression such as `X - X.mean(axis=0)` hands the whole loop to compiled code. That code walks contiguous memory with no per-element type checks, often using SIMD instructions that process several numbers at once.

The rule of thumb: **if you are writing `for i in range(len(x))` over array elements, there is almost always a whole-array expression instead.**

## Broadcasting: arithmetic between different shapes

Vectorized code constantly combines arrays of different shapes: subtract a per-column mean from a matrix, scale each sensor by its own gain. **Broadcasting** is NumPy's rule for when that's allowed and what it means. Compare the two shapes **from the right**, one axis at a time. Two axes are compatible when:

1. they are equal, or
2. one of them is 1. That axis is stretched, virtually and without copying, to match the other.

If an array has fewer axes, NumPy pads its shape with 1s on the left. So for `X` of shape `(129600, 360)` and `mu` of shape `(360,)`:

```text
X      : 129600 × 360
mu     :          360   →  padded to 1 × 360  →  stretched to 129600 × 360
X - mu : 129600 × 360
```

Every row of `X` gets the same 360 means subtracted, with no loop and no copy of `mu`.

## The broadcasting bug that ships

Broadcasting is also how silent bugs get into ML code. A model returns predictions shaped `(n, 1)` and your targets are shaped `(n,)`:

```python
y_true = np.array([20.1, 22.4, 21.0])        # shape (3,)
y_pred = model.predict(X)                    # shape (3, 1)
mse = np.mean((y_true - y_pred) ** 2)        # no error!
```

<Craft>
Defend against shape bugs at the boundaries of your functions:
- assert the shape you expect (`assert y_pred.shape == y_true.shape`);
- flatten predictions deliberately (`y_pred.ravel()`);
- pass `keepdims=True` when you want a reduced axis kept for broadcasting.

The grader in this course does the same: its messages tell you *which* shape it expected and what usually causes the mismatch.
</Craft>

## Your turn: standardize the sensors

Standardizing (z-scoring) puts every sensor on the same scale: subtract the column's mean and divide by its standard deviation. Many models, including every gradient-based one you will build, train badly without it. Two details matter:

- use the **population** standard deviation (`ddof=0`, NumPy's default), so the result has standard deviation exactly 1;
- a **stuck sensor** has standard deviation 0. Dividing by it gives NaN, and NaN silently spreads through every downstream computation.
